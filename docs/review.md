# 实现 review 与重构记录

本次改造以工作区现有内容为输入，保留 24 条模型名与日期，包括尚未提交的 3 条新增记录。数据内容没有被当作已核实的发布事实；名称后缀也没有用于自动改写日期。

## 已修复的问题

| 原实现问题 | 新实现 |
| --- | --- |
| 名称和日期分开维护，索引错位无法提前发现 | 逐条 JSON 记录，稳定 ID、严格 schema、日历日期、来源和重复检查 |
| 数据、训练、回测、绘图挤在一个千行脚本 | 数据层、预测注册表、分析层、CLI、报告渲染和前端源码各自独立 |
| 预测过期时跳过事件并不断追到未来 | 保留下一未观测事件的原始估计和逾期状态 |
| 无历史截断配置，历史模拟可能纳入未来数据 | 显式 as_of，训练和回测都只使用截止日之前的记录 |
| 线性首个样本用全局均值作为特征 | 缺少 lag 的首个间隔不作为回归样本；小样本回退到间隔基线 |
| 自适应趋势把整体均值当索引零点，趋势被重复叠加 | 对索引中心化，历史均值对应历史中心位置 |
| 季节性按未知目标月份训练，预测时却猜测目标月份 | 训练与推理都使用已知的间隔起始月份 |
| 周期预测从相位零重新开始，趋势预测可能锚定旧日期 | 周期从历史末端相位续接，趋势间隔从最后观测日推进 |
| 集成模型错误处理 MAE=0，平均子模型指标冒充整体指标 | 明确零误差和非有限值权重；对实际合成的拟合值计算诊断指标 |
| 失败结果混在无穷大误差中，记录容易丢失或错位 | 每方法每折完整记录成功/失败、训练截止、实际、预测与错误；未知值用 null |
| 失败模型可凭较少有效样本获得靠前的 MAE | 全折覆盖才参与排名，失败计入命中率分母，覆盖率明确展示 |
| 重训失败后可能保留上一次成功的训练状态 | 开始 fit 即失效旧状态；推理验证日期历史与 fit 一致 |
| 两个 CDN Plotly 大页面缺乏统一交互且源码难维护 | 单一离线 HTML，独立 HTML/CSS/JS 原生 SVG，支持搜索、筛选、排序和逐折联动 |

## 验证范围

自动化测试位于 `tests/`，包含数据迁移与校验、预测器数值回归、前缀回测、失败和空状态、严格 JSON、安全嵌入和 CLI 错误处理。依赖锁定于 `uv.lock`，本地在 Python 3.10 和 3.13 下分别运行，49 项测试均通过；CI 配置覆盖同样两个版本。

默认 2026-09-05 快照：24 条模型记录 / 24 个日期事件，12 种方法，21 折，共 252 条回测记录，全部预测与回测成功。逐个历史截断日检查后，自动截断完整目录与手动移除未来记录的分析结果一致。推进基准日不会改变从同一历史末端发出的预测序列。

## 结果边界

改造修复的是数据维护、计算一致性、评估和展示，不能从 24 条混合模型系列的记录中证明发布时间可预测。这里的一步回测无法直接支持多步预测的可靠性。完整覆盖条件保证误差可在同一组折次上比较，但在这些折次上选出的最佳方法仍有选择偏差。

目录只保存发布日期，没有保存资料的知悉时间。因此 as_of 表示按发布日期截断的模拟，不是严格的历史信息快照。旧脚本命令保留，旧类接口与旧 HTML 输出完全移除。

## 浏览器验收

通过本地 HTTP 在浏览器检查了最终报告：方法分组筛选、日期排序、点击方法联动 21 折明细、发布搜索与年份筛选、无搜索结果、零回测折次、全部方法失败和错误 HTML 转义均正常。390px 窄屏无页面级横向溢出，表格在自身容器内滚动，浏览器没有报告 JavaScript 错误。

浏览器工具的 URL 策略禁止访问 `file://`，所以没有直接实测双击 HTML 的本地文件模式。模板和输出测试确认没有外部脚本/样式链接，数据内嵌。导出按钮点击后没有 JavaScript 错误，但工具未收到下载完成事件，不能据此确认下载落盘；独立 `output/report.json` 文件已经生成并完成 JSON 校验。
